## 1. 結論（先に）

**論文の否定的結果は「アイディアが悪い」ことを示していない。示せる状態になっていない。** 理由は三層ある。

1. **グラフ枝（R-GCN 側）は実装バグで実質的に壊れていた。** 辺の種別ラベルが誤っており AST 関係と CFG 関係が同一集合になっている、Joern の `<global>` 疑似関数が全関数を二重化している、C++ 関数（入力の約 12〜15%）が C として解析されて 2 ノードの殻になっている、ノード特徴が未正規化でほぼ一定、論文 §3.2.2 の記号正規化は一切適用されていない。**構造情報がモデルに正しく届いていないので、「構造情報は有効でなかった」という結論は導けない。**
2. **比較実験として統計的に成立していない。** seed 固定なしの単一 run 同士の 1.89 点差。リポジトリ内の同一設定の再実行同士でも約 2 点ずれる。公表されている seed 間の標準偏差は 2.8〜3.5 点。さらに融合モデルはベースラインの上位互換になっていない（CLS 読み出しを捨て、ランダム初期化の 3 層 cross-attention 経由の平均プーリングに置き換えている）ので、グラフが無用でも差が出うる。図 2 のゲート解釈は、同一設定の別 run で再現しない。
3. **アイディア側にも、この設定で差を示すのが原理的に難しい理由がある。** BigVul はラベル正解率 25〜54%、重複 12.7% と報告されており、関数単位ランダム分割では言語モデル単体が既に強い。同一バックボーンでの既報の融合利得は +0.1〜+3 F1 程度で、単一 run の −1.9 はその帯の中。ノード特徴に CodeBERT の CLS を使う設計は、二つの枝を冗長にする（既報で効いている DeepDFA は識別子を含まない抽象データフロー特徴を使う）。

**重心はコードと実験設計にある。** ただし、バグを直しただけで BigVul ランダム分割で明確に勝てる保証はない。勝てる可能性がある設定（長い関数、プロジェクト横断分割、テキスト枝が持てない特徴）を選び直し、seed を振って信頼区間つきで比較することが次の一手になる（§8）。

以下は監査者（本報告の筆者）がコード・git・画像・外部データから直接確認したもの。

- 論文図 2 は `plots_Elevneth/weights_curve_bs16_lr1e-04_br0p30.png` と形が一致する。
- HEAD では CodeBERT 単体の学習経路が最初のバッチで落ちる（`run.py:474-492`: `w_c` は `model.fusion` がある時しか束縛されないのに `wandb.log` で参照。`except RuntimeError` では捕まらない）。

### 3.2 グラフ枝に届いているもの

実パイプライン形式のサンプル `data/check_data/cpg_head_check.json`（5 行）に、リポジトリの `parse_to_functions` → `build_edges_all` → `nodes_to_input` をそのまま適用して確認した。

- **辺種別の誤ラベル。** Joern が出した辺は AST 67 / CFG 59 / PDG 37 の計 163 本（辺自身の `type` 欄）。パーサ（`utils/functions/cpg.py:153-163`）は辺の `type` を読まず、**その辺が載っているリスト名（AST/CFG/PDG）**を種別にする。各ノードは自分の全辺を持ったまま AST と CFG の両リストに現れるので、結果は 405 本・{AST:158, CFG:158, PDG:89}、全 158 の (src,dst) ペアが 2〜3 種のラベルを重複して持ち、Joern の種別と一致するのは 163 本だけ。**AST 関係 ≡ CFG 関係** で、R-GCN の関係別重み W_r は意味を失う。`git log -S'e.get("type")'` は空で、最初から一度も辺の型を読んでいない。
- **`<global>` による二重化。** `cpg_generator.graph_indexing`（`:120-133`）はファイル名が数字なら全メソッドを通すので、Joern がファイルごとに作る `0.c:<global>` 疑似関数も通る。サンプルの Index は 0, 0, 1, 1, 2 で、**同じ関数・同じラベル・同じ `func` 文字列のグラフが 2 行**ずつ入っている。`<global>` 側は PDG 0 本・CFG 10 本。学習ではハイブリッドだけが半分近く構造の乏しいグラフを見せられ、評価では各関数が 2 回採点される。
- **C++ 関数の混入。** `datamanager.to_files`（`:89-93`）は全関数を `{idx}.c` で書き出す。Joern 入力サンプル 1,500 件中 188 件（12.5%）が `::`・メンバ初期化子・`this->` などの C++ 構文を含む（例: `void CClient::ClearServerDependentCaps()`）。これらは C として解析され、監査エージェントの計測では `<global>` のみの 2 ノード自己ループグラフになる。
- **記号正規化は未適用。** 論文 §3.2.2（FUN_i / VAR_j）に相当する `parse.tokenizer` は `data.tokenize` 経由で `tokens.pkl` に書かれる（`run.py:351-352`）だけで、**どこからも読まれない**。Joern への入力 `.c` もノードの `CODE` も生のソース（例: `am_xstrtok(r, m, "\n", &l1)`）。HEX 置換・非 ASCII 除去も同じ未使用経路にある。
- **論文 §3.3.1 の 3 種の辺自体は存在する**（Joern 出力に AST / CFG / PDG が入っている）。壊れているのはそれを読む側。
- **ノード特徴は論文の記述と違う。** 「ノードのトークン」ではなく Joern の `CODE` プロパティ全文（128 トークンで切る）の CLS。BLOCK ノードの `CODE` は関数本体全文（サンプルで 491 字、274 トークン）。つまりグラフ枝の中に「関数全文の凍結 CodeBERT 埋め込み」というノードが入っている。

### 3.3 データと手続き

- **未開示の関数長フィルタ。** `run.py:170` `len(func) < 1200` が最初のコミットからあり、論文に記載がない。BigVul の公開ミラー（HF `bstee615/bigvul`, train 150,908 行）から 4,000 行を無作為抽出して測ると、**非脆弱関数は 84.2% 残るが脆弱関数は 65.5% しか残らない**（中央値 375 字 vs 820 字）。陽性率は 5.65% → 4.45%。構造情報が効きそうな長い関数ほど捨てている。分母: 抽出 4,000 行、`func_before` の文字数、コメント除去前。
- **学習データの固定・同一順序。** `--subset_frac` の既定値は 0.10（`run.py:1117`）で、`LimitedStreamDataset` はストリームの**先頭 N 件**を取る。`StreamGraphDataset.__iter__` は毎 epoch `random.Random(42 + pid)` を作り直す（`run.py:829`）ので、**順序は毎 epoch 同一**。最終 run が `--no_subset` だったかは記録がない（README の例にはある。スイープのディレクトリ名は 10%）。
- **Focal loss の実装誤り。** `FocalLoss.forward` は `F.cross_entropy(..., weight=alpha)` の結果から `pt = exp(-ce)` を計算するので `pt = p_t^{α_t}` になる（`run.py:84-88`）。α₁ ≈ 16.7 の陽性では `(1 - p^{16.7})²` がほぼ 1 のままで focal の減衰が効かず、陰性（α₀ ≈ 0.52）は逆に過剰に減衰する。全 200 epoch run が「最初の約 10〜25 epoch は全件陽性予測（recall 1.0、precision 0.03）」から始まるのはこれと整合する。**両腕共通**なので差の説明にはならないが、論文 §4.3 の式 (12) とは違うものが学習されている。
- **グリッドサーチは別のモデルで行われた。** 2 つのスイープディレクトリ（各 36 設定）には `weights_curve` が 1 枚もない（`f633e44` 以降の run は必ず出す）。損失の初期値もクラス重みつき CE の値。つまり **ゲートも Focal loss も CodeBERTOnly もない時代**のモデルで、**10% 固定サブセット・patience 5** で探索し、その設定（bs16, lr 1e-4, ratio 0.3）を最終のハイブリッドとベースラインに移植している。スイープ内の最良は val F1 ≈ 0.18（README の SWEEP SUMMARY と一致）で、設定間の差は雑音水準。
- **検証ループの二重計上（HEAD のみ）。** `validate()` が `y_true` / `y_pred_labels` を 1 バッチにつき 2 回 extend（`run.py:569-576`）。比率は変わらないので P/R/F1 は正しいが、混同行列の件数は 2 倍。論文時点のコードにはない。

### 3.4 学習曲線が語ること

- 訓練損失（重みつき focal）は epoch 50〜100 で ≈ 0、検証損失（素の CE）は横ばい（`plots_Elevneth`, `plots_12`）または上昇（`plots_codebert_first`: 最小 0.18 → 0.42）。**過学習**。
- 検証の P(y=1) ヒストグラムは epoch 100 以降 [0, 0.05] と [0.95, 1] の二山で中間が空。論文 §4.2 の閾値探索はこの状態では動かない。
- 融合層数 1 / 3 / 5（`plots_bigvul_attn1/3/5`）は全て val F1 ≈ 0.40〜0.42。**融合の深さは効いていない**（ただしゲート導入前のモデル）。
- ゲート: `plots_Elevneth`（論文図 2）は epoch 135 以降 CodeBERT 0.8 で落ち着くが、**同一設定の `plots_12` は 200 epoch 通して 0/1 と 1/0 を往復し、最後は R-GCN 0.7 で終わる（val F1 は同じ ≈ 0.44）**。`plots_selfatention` ではゲートが epoch 11 で R-GCN = 1.0 に飽和し、出力が定数になって F1 0.07 のまま終わる。`plots_Elevneth` 内でも、ゲートが R-GCN ≈ 1.0 の区間（ep 45〜72）と CodeBERT ≈ 0.8 の区間（ep 135〜200）で val F1 は同じ 0.40〜0.43。
- `plots_codebert_first` はゲート曲線が全 epoch で 0.0（`fusion` を持たないモデルに対して学習ループが書く値）なので、**これが CodeBERT 単体の run** と同定できる。その曲線はハイブリッドと区別がつかない（同じ全件陽性の立ち上がり、同じ水準の plateau、同じ確率の二極化）。

## 5. なぜ「構造情報は有効でなかった」と言えないのか

論文 §5.1・§6 は「CPG の構造情報は十分な付加価値を持たなかった」と結論づけている。しかし R-GCN に渡っていたのは次のものである。

1. **関係ラベルが壊れた辺集合**（M19）。R-GCN の式 (3) は関係 r ごとに W_r を持つことが前提だが、AST と CFG が同じ辺集合、PDG には AST/CFG が混入している。関係別の重みは学習しようがない。
2. **約半分が `<global>` の複製**（M20）。PDG を持たない方の複製も同じラベルで学習される。
3. **約 1/7 が 2 ノードの殻**（M21）。
4. **ほぼ一定のノード特徴**（M13）。CLS ベクトルは異方性が強く、どのノードも同じ方向を向く。入力正規化がないので、`input_proj` の勾配は定数成分に支配される。
5. **論文が前提にした前処理（正規化・コメント除去）なし**（M23）。
6. **関数全文の埋め込みを持つノード**（M22）。グラフ枝の中にテキスト枝と同じ情報が入り、「構造 vs 意味」の切り分け自体が成り立たない。

この状態での「グラフ枝の寄与が小さい」は、構造情報の価値ではなく実装の状態を測っている。

## 6. なぜ比較が成立していないのか

### 6.1 差は雑音の中

- seed 未固定（`run.py` に seed 設定なし。`models/layers.py:12` の `torch.manual_seed(2020)` は import 時の一度きりで、CUDA の非決定性とデータ順序は制御されない）。
- 各腕 1 run。同一設定のハイブリッド 2 run（`plots_Elevneth` vs `plots_12`）で val F1 plateau が 0.42 vs 0.44。
- 既報の seed 間 std: CodeBERT 2.78、LineVul 3.46、ReGVD 7.33（Steenhoek+ ICSE 2023）。テスト陽性 ≈ 500 件の二項ばらつきだけで ±2 F1。
- したがって 43.85 vs 45.74 は「同じ分布からの 2 回の抽出」で説明できる。

### 6.2 ハイブリッドはベースラインの上位互換ではない

ベースラインは事前学習済み CLS を直接分類する。ハイブリッドのテキスト経路は CLS を捨て、ランダム初期化の射影 → 3 層の双方向 cross-attention → 全トークンの平均 → FFN → LayerNorm を通す（M12）。ゲートが α_graph → 0 に振り切れてもベースラインには戻れない。**「グラフを足した」のではなく「読み出し方を変えた上でグラフも足した」**比較になっており、1.9 点の差は読み出しの変更だけでも生じうる。

### 6.3 図 2 の解釈

ゲートは「3 回互いを参照し終えた 2 本のストリーム」を重みづけしている（`layers.py:306-311, 337-356`）。片方の重みが大きくても、もう片方の情報は残差経由で既に混ざっている。実際、同一設定の別 run ではゲートが 200 epoch 振動し続けて R-GCN 0.7 で終わり、論文 run の中でもゲートが R-GCN 1.0 の区間と CodeBERT 0.8 の区間で F1 は変わらない。**ゲートの値は性能と切り離されており、「モデルが意味情報を優先するようになった」という読みは支持されない。** ゲートが 0/1 に飽和して出力が定数になった run（`plots_selfatention`）もある。これは M15 のゲート設計（温度・正則化なしの softmax）の帰結。

### 6.4 手続き上の問題（両腕共通だが、絶対水準を下げている）

- Focal loss の実装誤り（M01）→ 全件陽性からの立ち上がりと、陰性の過剰減衰。
- グリッドサーチが別モデル・別損失・10% データ・patience 5（M04）。最終モデルは実質未調整。
- 最後の 2 層のみ学習 + 1200 字フィルタ → ベースライン 45.74 は既報（54〜93）より大きく低い（M31）。**両腕とも under-trained** な状態で順位を比べている。
- 出力飽和後の雑音最大でチェックポイントを選択（M30）。閾値探索は飽和後には動かない。
- 1200 字フィルタ（M28）が脆弱関数の 1/3 を捨て、構造が効く長い関数を除外。
- アブレーションがない（M32）。

## 7. アイディア側の限界と、文献からの予測

収集した数値（出典・検証フラグは `audit/finder_results.json` の literature 要約に一覧）:

| 論文 | 設定 | 数値 |
|---|---|---|
| Vul-LMGNNs (Inf. Fusion 2025) — 本リポジトリの系譜元 | CodeBERT → 融合 | DiverseVul 23.44→23.54、Devign 59.53→60.16、VDSIC 82.39→83.87、ReVeal 38.19→51.22。BigVul なし |
| DeepDFA + LineVul (ICSE 2024) | BigVul 80/10/10、3 seed | LineVul 93.23(±0.31) → 96.40(±0.13)。プロジェクト横断: 71.37 → 71.88。DeepDFA 単体はプロジェクト横断で −1.9 しか落ちない（LineVul は −12.7） |
| LineVul (MSR 2022) / Steenhoek+ 再現 | BigVul ランダム分割、dedup なし | F1 91〜92 |
| PDBERT (ICSE 2024) | BigVul 80/10/10 | CodeBERT 54.48、GraphCodeBERT 54.06 |
| PrimeVul (Ding+ 2024) | BigVul → PrimeVul | CodeBERT 62.88 → 4.49。BigVul のラベル正解率 25%、複製率 12.7% |
| Croft+ (ICSE 2023) | BigVul 手動監査 70 件 | ラベル正解率 0.543、重複排除率 0.830 |
| Steenhoek+ (ICSE 2023) | 3 seed の std | CodeBERT 2.78、LineVul 3.46、平均 2.9。予測の 34.9% が seed で反転 |
| GALLa (ACL 2025) | Devign (C) accuracy | グラフエンコーダは推論時に捨てる。モデルによっては低下 |

読み取り:

1. **効果量の期待値は小さい。** 同一バックボーンで融合しても BigVul ランダム分割では +0〜+3 F1。seed std ≈ 3 と同じ桁なので、1 run では検出できない。
2. **構造が効くのは分布が変わる場面。** DeepDFA はプロジェクト横断で崩れにくい。BigVul ランダム分割はテキスト枝に最も有利な設定。
3. **ノード特徴の設計が決定的。** 既報で効いているのは、テキスト枝が持っていない情報（DeepDFA: 識別子を含まない抽象データフロー特徴）か、ノードエンコーダを共同学習するもの（Vul-LMGNN）。本研究のように凍結 CodeBERT の CLS を各ノードに置くと、二つの枝は同じ情報の別表現になり、最適なゲートはテキスト側に寄るのが理屈どおりになる。
4. **データの天井。** ラベルの半分近くが疑わしいデータセットでは、どの手法も上限が低く、小さな差は見えない。

結論: アイディアは「無意味」ではないが、**この設定（BigVul ランダム分割 + 短い関数のみ + CLS ノード特徴 + 単一 run）では、正しく実装しても差を示せない公算が高い**。論文の否定的結果はアイディアの否定にはならないし、肯定にもならない。

## 8. 推奨する次の一手（優先順）

### 8.1 まずグラフ枝を直す（これなしに何も言えない）

1. `cpg.py:_gather_edges_from_blocks` で辺自身の `e["type"]` を使い、`kind`（リスト名）は使わない。修正後、サンプルで Joern の辺数（163）と一致することを確認する。
2. `cpg_generator.graph_indexing` で `function` 名が `<global>` で終わるメソッドを捨てる。学習・評価の行数が関数数と一致することを確認する。
3. C++ を判定して `.cpp` で書き出す（または `lang` 列を使う）。2 ノードグラフの件数をログに出す。
4. ノード特徴を正規化する（`input_proj` の前に LayerNorm、または CLS を中心化）。Joern のノードラベルを埋め込みとして足す（1 ビットではなく）。
5. 論文 §3.2 を実際に適用するか、論文の記述を実装に合わせる。
6. `FocalLoss` は重みなし CE から p_t を計算し、α は外側で掛ける。
7. ストリームの RNG を epoch ごとに変える。`--no_subset` の有無を保存する設定に残す。

### 8.2 比較が成立する形にする

8. **ハイブリッドをベースラインの上位互換にする。** 例: 事前学習済み CLS 経路を残し、融合出力と結合する。ゲートの初期値をテキスト側に置く。または融合をスキップ接続で包む。
9. **アブレーション**: graph-only、ランダム辺（辺をシャッフル）、ゲートなし結合、融合凍結。ランダム辺で性能が変わらなければ構造は使われていない。
10. **seed を 3〜5 個振り、平均 ± 標準偏差と同一テスト集合上の対応つき比較（bootstrap 信頼区間）**で報告する。閾値 0.5 の行と調整後の行を両方載せる。
11. 全層 fine-tune（または最後の 4〜6 層）で両腕の絶対水準を既報の帯（54〜63）に乗せる。グリッドサーチは最終モデル・最終損失で、全データで行う。

### 8.3 構造が効きうる設定で問う

12. 1200 字フィルタを外す。512 トークンを超える関数こそテキスト枝が切り捨てる領域で、グラフ枝の出番になる。長さ別に F1 を層別報告する。
13. プロジェクト横断分割、または PrimeVul / DiverseVul での評価を加える。
14. ノード特徴を、テキスト枝が持てない情報（抽象データフロー、型、API カテゴリ、ノードラベル）に変える。CLS を使うなら共同学習する。

### 8.4 再現性の最低限

15. `graph-for-funcs.sc` と Joern のバージョンをコミットする。`os.chdir` と絶対パスを消す。`pyvis` 等を requirements に足す。
16. テストの数値（P/R/F1/Acc、閾値、epoch、seed、コミットハッシュ）を JSON で保存し、チェックポイントのファイル名を腕ごとに分ける。
17. 論文の図表を作る run には、そのコミットハッシュとコマンドラインをディレクトリ名ではなくファイルで残す。
